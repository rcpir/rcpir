# RC-PIR (√n, LPN over F_2) — Specifications

Scheme: the RC-PIR construction "Optimized Toy Example" (Hadamard-based PIR with dual LPN over $\mathbb{F}_2$). All specs below are agreed.

| Document | Content |
|---|---|
| `lpn_parameters.md` | Security target, attack bounds, parameter selection (Mode A / Mode B), defaults, reference values |
| `db_format.md` | JSONL input, block → column encoding (u32 BE header), MSB-first bit order |
| `params_format.md` | `params.json` fields, validation, `/.well-known/rc-pir.json` |
| `h_prg.md` | `aes128-ctr-col-v1`: expansion of `h_seed` into $H$ |
| `protocol.md` | HTTP protocol: shards of $R$ and byte-range fetches, compute endpoints, client flow, browser/CORS requirements |
| `stack.md` | Components and languages, repository layout |
| `encoder.md` | Encoder CLI and tiled GPU pipeline |
| `compute_server.md` | Compute server internals, batching, evaluation knobs, benchmark harness |

## Testing

| Level | What | Run |
|---|---|---|
| Cross-language vectors | `testvectors/vectors/*.json` (`h_prg`, bit packing, $q_c$, column paths, `db_format`, `params.json` fixtures), generated by `testvectors/gen.py` from `common/` and consumed by every component (next row) | `gen.py --check` |
| Components | Each component's unit tests **and** its conformance against the vectors: `common/tests`, `encoder/tests/test_vectors.py`, `client/test/vectors.test.ts`, `server/crates/rcpir-core/tests/vectors.rs` | `pytest common encoder`, `npm test`, `cargo test` |
| Full scheme | Encoder verify step (spot check of 1000 random columns of $R=XH$); `e2e/run.sh` (encoder → static server + compute server → client, plain HTTP and HTTPS, insecure and secure parameters) | `e2e/run.sh` |

`scripts/test-all.sh` runs everything.
